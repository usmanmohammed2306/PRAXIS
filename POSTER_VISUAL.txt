THE CORE IDEA  (The Analogy)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Imagine a team of four workers tackling customer service tasks.

  👤 Act          completes 200 tasks  →  experiences logged
  👤 ReAct        completes 200 tasks  →  experiences logged
  👤 Vanilla TC   completes 200 tasks  →  experiences logged

  🧠 PRAXIS  watches all three.
     It takes no raw data — no order IDs, no emails, no payment details.
     It takes only the lesson:  "what sequence worked, what failed, and why."

  When PRAXIS performs its own tasks, it reaches into that growing memory
  every 2 steps, pulls the 5 most relevant lessons, and reasons better.
  After completing its run, its own experiences join the memory too.

  The memory is permanent.  Every future run starts smarter than the last.

                "An agent that learns from every interaction —
                 not just its own."

DIAGRAM 4 — MUTATION REFLECTION GUARD
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Every tool call:

  READ tool?   ──▶  Execute immediately.  No delay.

  WRITE tool?  ──▶  Pause.  Ask the same model:
                    "Do observations confirm this action is safe & requested?"

                    ALLOW  ──▶  Execute
                    BLOCK  ──▶  Explain to user, ask for confirmation

  Write tools are things like: cancel order, modify reservation,
  process return, transfer to human.

  Read tools are free.  Only irreversible actions are checked.

FUTURE WORK
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. CROSS-DOMAIN TRANSFER
     Can a retail lesson about "verify before mutating" help an airline agent?
     Memory is currently siloed per domain.  Cross-domain generalization would
     let retail experience bootstrap an airline agent from day one.

  2. ACTIVE MEMORY QUERYING
     Currently PRAXIS retrieves passively every 2 steps.
     Future: let the agent explicitly say "I don't know how to handle this —
     retrieve past failures for modify_reservation."  Agent-initiated recall.

  3. MID-TASK ONLINE DISTILLATION
     Currently distillation happens after a run completes.
     Future: distill lessons within a single trajectory.  If the agent hits
     a failure at step 5, immediately learn and adjust by step 8.

  4. MULTI-AGENT SHARED MEMORY
     Multiple PRAXIS instances (across customers, teams, or organizations)
     contribute to a shared federated memory bank — while each keeps its
     private task data completely local.

  5. CONFIDENCE CALIBRATION VIA OUTCOME FEEDBACK
     Today quality scores are estimated at distillation time.
     Future: feed live success/failure signals back to update card confidence
     dynamically, so bad advice gets demoted and good advice promoted faster.

  6. HIERARCHICAL MEMORY
     Three tiers:  task-level (this specific exchange type) ·
                   session-level (this user's preferences today) ·
                   global (cross-user patterns over time)
     Currently only global.

  7. ADVERSARIAL MEMORY ROBUSTNESS
     What if a corrupted trajectory injects bad lessons?
     Future: adversarial auditing of new cards before promotion, with
     human-in-the-loop review for low-confidence insertions.

  8. MEMORY-GUIDED EXPLORATION IN RL
     Use memory cards as reward shaping signals in reinforcement learning.
     Cards that reflect high-reward sequences become intrinsic rewards for
     a fine-tuned variant — bridging procedural memory and policy learning.
